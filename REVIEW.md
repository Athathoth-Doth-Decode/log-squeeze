# Ревью log-squeeze v0.2.0

## Третий этап: дедупликация, порядок и бюджет (2026-11-08, рабочее дерево)

Исправлены воспроизведения **I1–I4**. Разделы ниже сохраняют историю предыдущих
этапов, включая прежние ограничения и результаты проверок. Коммитов, публикации
и установки бинарника не было; реальный пользовательский конфиг не менялся.

| Пункт | Результат третьего этапа |
|---|---|
| **I1** | ERROR/WARN/PANIC/FATAL объединяются только при совпадении диагностических значений после redaction и нормализации ведущего timestamp. `code=13` и `code=14`, адреса и другие значения не теряются при объединении. Отдельные числа 100–599 сохраняются в шаблонах всех уровней: 200/500/502/200 дают три кластера с частотами 2/1/1. Значения не объединяются в набор, поскольку остаются разными событиями. |
| **I2** | Выбираются индексы, затем вывод восстанавливает порядок первого появления кластеров. Приоритет ошибки влияет на выбор, но не переносит её перед более ранними выбранными событиями. Маркеры `N events skipped` показывают пропущенные группы; число учитывает частоту пропущенного кластера. |
| **I3** | Tier 1 соблюдает жёсткий лимит физических строк, включая заголовок, оформление, стеки, `-e` и `-s`. Усечение явно помечено. `-m 1` оставляет заголовок и счётчики пропусков, ноль отклоняется до обработки входа. JSON получает ту же выборку и пишется одной строкой; `stats.output_lines` теперь заполнен. |
| **I4** | Глобальный индекс использует уровень, идентичность заголовка и полный нормализованный стек. 40 несмежных NPE с меняющимися номерами строк объединяются в `[x40]`; разные причины и свойства Node остаются разными кластерами. Сохраняются первый/последний заголовки и первый представительный стек. |

`src/masker.rs` собирает события до глобального объединения. Для ошибок и
предупреждений общий маскированный шаблон больше не служит критерием равенства:
идентичность сохраняет все значения после ведущего timestamp. Для остальных уровней
остаётся сравнение шаблонов. В стеках нормализуются только распознанные кадры
местоположения (at/File, Go-файлы/горутины, нумерованные Rust-кадры); строки кода,
причины исключений и объектные свойства сравниваются без маскировки. Исходные
секреты не участвуют ни в одном сравнении.

`src/output.rs` отделяет выборку и рендеринг от кластеризации. Сначала резервируется
строка заголовка, затем выбираются заголовки событий по приоритету
PANIC/FATAL/ERROR/WARN/прочие; при равенстве — по первому появлению. Остаток бюджета
выделяется кадрам в том же приоритетном порядке. Оформление стека можно убрать,
чтобы вместить кадры. Маркеры пропусков занимают часть уже выделенной строки.
Так сохраняется верхняя граница даже при бюджете 1 или 2 строки. Частотная сводка
сортируется по убыванию числа повторов, затем лексикографически; скрытого top-25
теперь нет, число строк определяется бюджетом.

JSON содержит выбранные события, а не полный набор до ограничения. При потерях
добавляются `budget` и ненулевые поля кластеров `skipped_before` /
`omitted_stack_lines`. `skipped_after` описывает хвост выборки. Числа пропущенных
событий учитывают повторы, а число строк стека относится к представительным
стекам кластеров. Нулевая метаинформация не добавляется. `stats.output_lines`
равен фактическому числу строк (для JSON — 1); статистика severity остаётся по
полному входу. Старые JSON-эталоны обновлены только для этого счётчика, а шаблоны
security-тестов — для сохранения HTTP-кода 500; проверки redaction не ослаблены.

Проверки:

- Сначала добавлены 6 регрессий; все упали на реализации второго этапа. Затем
  добавлены ещё 3 теста парсинга/выборки и 3 CLI-теста с временным HOME.
- Точные результаты для 200/500/502, небольших кодов ошибок, несмежных повторов,
  timestamp, 40 одинаковых стеков, разных причин и Node-полей. Номера кадров
  проверены по обе стороны границы 99/100.
- В потоке из 1000 событий ERROR на позиции 501 остаётся после восьми выбранных
  ранних INFO при бюджете 10; пропущено ровно 492 события перед ней и 499 после.
  1000 различных ошибок при `-e -m 5` дают ровно 5 строк, включая заголовок;
  250 кадров при бюджете 200 сохраняют 198 кадров и пометку о 52 пропущенных.
- Точные stdout/JSON для обычного режима, auto и `-e`, бюджеты 1 и 0, конфиг и
  CLI override, одинаковая выборка в обоих форматах. Локальная HTTP-заглушка и
  подставной uv подтверждают локальность auto; все старые security-тесты сохранены.
- Частотные сводки проверены на лексикографический порядок при одинаковой частоте,
  несколько отдельных CLI-процессов и бюджеты от 1 строки.
- `cargo test`: **17 unit + 47 integration = 64 теста**, все прошли.
  Проверки выполнены с `CARGO_NET_OFFLINE=true`; внешние зависимости не скачивались.
- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` и
  `git diff --check`: успешно.

Границы результата: глобальные кластеры расположены по первому появлению, а не
воспроизводят каждое повторное вхождение в исходной временной позиции. Для
ERROR/WARN меняющиеся request ID или timestamp внутри JSON/logfmt могут мешать
объединению: сохранение диагностики важнее полноты сжатия. Шаблоны менее серьёзных
уровней остаются потерей части динамических значений. Жёсткий лимит относится к
Tier 1, а не к результатам Tier 2 или ответу модели Tier 3; не ограничивает длину
строки в байтах и переносы терминала. I9 (память), I12 (не-UTF-8/broken pipe),
структурный Tier 2, ограничения C1 и нестандартных стеков не закрыты этим этапом.

| Вопрос для ревью | Ответ |
|---|---|
| Почему разные коды ошибки не склеятся? | Ключ ERROR/WARN сохраняет диагностические значения, даже если общий шаблон совпал. |
| Не передвинется ли ошибка в начало? | Приоритет выбирает индексы; вывод всегда сортирует их по первому появлению. |
| Что произойдёт с длинным стеком? | Сохранятся доступные строки, остальные будут явно посчитаны в тексте и JSON. |
| Как увидеть повторения после других событий? | `[xN]` и последний пример обновляются в первом кластере; представительный стек берётся из первого вхождения. |
| Можно ли считать бюджет ограничением памяти или байтов? | Нет, это лимит строк Tier 1; соответствующие открытые пункты ревью остаются. |

## Второй этап: уровни и стектрейсы (2026-11-08, рабочее дерево)

Реализованы исправления описанных воспроизведений **C3, C4 и I5**. История первого
этапа и исходное ревью сохранены ниже; приведённые там прежние результаты относятся
к соответствующим версиям. Коммитов, публикации и установки бинарника не было;
реальный пользовательский конфиг не менялся.

| Пункт | Результат второго этапа |
|---|---|
| **C3** | klog I/W/E/F распознаётся как новый заголовок. Фикстура из 8 записей даёт 8 событий, 4 INFO, 1 WARN, 3 ERROR и ни одной ложной строки стека. Упоминание `.go:`/`.rs:` без синтаксиса кадра больше не запускает продолжение стека. |
| **C4** | Добавлен автомат блоков Go/Python/Rust/Java/Node. Go сохраняет горутины, сигналы, функции и файлы; Python — traceback, исходный код, указатели ошибок и цепочки исключений; Rust — сообщение panic, кадры, исходные позиции и note; Java — исключения без сообщения, Caused by/Suppressed; Node — объектный хвост errno/code/port и поля с именами error/info/fatal. `-e` и `-e -j` сохраняют проверенные блоки. OOMKilled, Out of memory/Killed process и segfault распознаются как ошибки. |
| **I5** | Явный уровень имеет приоритет над текстом сообщения. Поддержаны JSON, klog, начальные текстовые/скобочные уровни, timestamp/thread/syslog-префиксы, разделители `-`, `\|`, `:` после timestamp и logfmt вне кавычек. Без явного уровня используются отдельные слова и сигнатуры сбоев вместо поиска подстрок. |
| **I3/I4** | Полностью не закрыты: убран только скрытый лимит 30 строк стека; событие собирается до дедупликации, чтобы следующий стек не терялся при одинаковых заголовках. Жёсткий бюджет, глобальная дедупликация и объединение повторных стеков не реализованы. |

`src/levels.rs` отвечает за уровни и границы новых записей; `src/trace.rs` — за
сборку событий. Сначала распознаются top-level JSON и klog, затем начальный
текстовый уровень, затем logfmt. Это сохраняет INFO для `INFO no panic detected`,
`[INFO] ERROR counter=0` и `INFO sample payload level=error`. Строка
`msg="level=error" level=debug` остаётся DEBUG. Pino 10/20/30/40/50/60 соответствуют
TRACE/DEBUG/INFO/WARN/ERROR/FATAL; неизвестное явное значение даёт Unknown.

Кадры наследуют уровень родительского события. `unwrap_failed` внутри Rust-стека
не создаёт новую ошибку, а traceback после WARN остаётся частью WARN. Счётчики
severity учитывают события до дедупликации; `total_lines` по-прежнему включает
кадры и пустые строки. Внутренние пустые разделители стеков сохраняются, хвостовые
пустые строки перед новым событием не присоединяются. Независимые traceback-блоки
не объединяются без явного маркера цепочки исключений.

Проверки:

- Всего добавлены 14 тестов парсинга в `tests/log_events.rs` и 3 CLI-теста. Проверены
  уровни, счётчики, полные массивы кадров, новый заголовок внутри каждого вида
  стека, Python-цепочки, родительский WARN, одинаковые заголовки с разными стеками
  и 45 кадров без потери хвоста.
- Ручные фикстуры `tests/fixtures/events/traces.errors.txt` и `.json` задают точные
  ожидаемые результаты. Вход из 55 строк даёт 5 ошибок со стеками длиной
  10/12/9/6/7 строк и 6 отдельных INFO-событий. Секреты в исходных кадрах заменены
  на `<REDACTED>`; локальная заглушка подтверждает отсутствие запросов из auto/`-e`.
- `cargo test`: **17 unit + 35 integration = 52 теста**, все прошли. Все регрессии

На реализации с 46 проходящими тестами воспроизведены все три новых замечания.

  также простой класс, вложенный класс с `$`, `AssertionError` и отрицательные
  случаи `NullPointerException.java` / `exception_count=0`. Явный INFO сохраняет
  приоритет над именем исключения в сообщении.
- Границы нового события отделены от контекста стека. После Python `File` одна
  строка с большим отступом считается исходным кодом, даже если начинается с
  `INFO`, `ERROR`, `level=` или JSON-уровня. Указатель `~~^~~` и завершающее
  исключение сохраняются. Это исключение действует только на одну строку после
  кадра, а не на все последующие заголовки с отступом.
- В открытом диагностическом объекте Node строки свойств `error:`, `info:` и
  `fatal:` сохраняются вместе с последующими полями и закрывающей скобкой.
  Проверены несколько полей, вложенный объект и redaction пароля внутри стека.
  klog, timestamp и syslog по-прежнему начинают новые события даже с отступом
  внутри незавершённых Python/Node-блоков. Обычные INFO/logfmt-записи вне позиции
  исходного кода или свойства объекта также остаются отдельными событиями.
- `2026-11-08 10:00:00,123 - INFO - no panic detected` и вариант с `ready`
  получают INFO. Покрыты разделители `-`, `|`, `:`, вариант без пробелов,
  timezone и thread label. Текст сообщения не переопределяет найденный уровень.

Фикстуры `tests/fixtures/events/review-regressions.log`, `.errors.txt` и
`.errors.json` фиксируют точный результат: 18 входных строк, 4 ERROR, 1 WARN,

неоднозначные строки без такого префикса разбираются по текущему контексту.
Не изменены структурный Tier 2, общий бюджет/выборка и её порядок, глобальная

### Допроверка обходов redaction

Первоначальная отметка C1 «исправлен» снята после воспроизведения найденных утечек.
Три новые unit-регрессии сначала падали на прежнем коде, затем прошли после исправлений.
Границы query-параметров теперь отделены от обычных полей: `&` не обрывает пароль
в логе или YAML. Plain scalar в блочном YAML скрывается до конца строки либо комментария.

отсутствующая закрывающая кавычка не добавляется. URL распознаётся и с `\/`, при этом
исходное экранирование и адрес назначения сохраняются.

| Регрессия | Точный результат redaction |
|---|---|
| `password: FAKE_FIRST&FAKE_SECOND` | `password: <REDACTED>` |
| `ERROR password="FAKE_UNTERMINATED` | `ERROR password="<REDACTED>` |
| `{"url":"postgres:\/\/fake:FAKE_PASSWORD@db\/app"}` | `{"url":"postgres:\/\/<REDACTED>@db\/app"}` |

Дополнительно покрыты одинарные кавычки, escaped quote, завершающий backslash, CRLF,
полезная следующая строка, вложенный `token=` внутри пароля, YAML-комментарий,
реальные query-разделители и экранированные mongodb+srv/redis/HTTPS URL.

проверены с переводом строки и без него. Это подтверждает устранение перечисленных

### Счётчики `[xN]` и склейка разных ошибок

Счётчики арифметически верны, но под одним `[xN]` оказываются **разные** события: маскировка
заменяет отдельные числа на `<N>`, а выводятся только первый и последний пример.

```
$ printf '%s\n' "2026-11-07T10:00:00Z [http] GET /checkout 200 12ms" \
                "2026-11-07T10:00:01Z [http] GET /checkout 500 13ms" \
                "2026-11-07T10:00:02Z [http] GET /checkout 502 9ms" \
                "2026-11-07T10:00:03Z [http] GET /checkout 200 11ms" | $LS -1
=== [log-squeeze] Total: 4 lines | Compressed to: 1 events (75.0% reduction) | Errors: 0 | Warnings: 0 ===
[x4] [LOG] 2026-11-07T10:00:00Z [http] GET /checkout 200 12ms ... [last: 2026-11-07T10:00:03Z [http] GET /checkout 200 11ms]
```

**Исправление примера:** исходный вариант с `T1/T2/T3/T4` не воспроизводит склейку: регулярное
выражение `\b\d+\b` не маскирует цифры, примыкающие к букве `T`, поэтому получаются четыре
разных шаблона. Вариант с настоящими timestamp выше проверен на release-сборке: оба 5xx исчезают.

Оба 5xx исчезли. То же с кодами ошибок (`code=402/500/401/503` → `[x4]`, видны только 402 и 503)
и с разными хостами (`10.0.0.1:5432` и `10.0.0.2:6379` → `[x2]`).

### Порядок событий

При превышении бюджета (`masker.rs:354-383`) **все ERROR/WARN поднимаются в начало вывода**,
а события INFO идут после них. На логе из 1000 строк ERROR из строки 500 и WARN из строки 900 стоят
на позициях 3 и 4, перед INFO из строки 1. Хронология, нужная для поиска причины, разрушена.

### Бюджет и дедупликация

- Дедупликация только **последовательная** (README обещает «global»). На реалистичном логе 200k строк
  заголовок честно пишет `Compressed to: 200061 events (0.1% reduction)`. Сжатие по байтам 99% получается
  только за счёт выборки «1 из N», которая выбрасывает 99% строк INFO.
- `max_lines` — это не лимит строк: при бюджете 200 выводится 2407 строк (все 2039 ERROR/WARN + стектрейсы).
  С `-e` бюджет не применяется вовсе: 40 событий при `-m 5` дали 161 строку.
- Одинаковые ошибки со стектрейсом **никогда не склеиваются** (`masker.rs:272` требует пустой стек):
  40 одинаковых NPE → 40 событий, 160 строк.
- Стек длиннее 30 строк: фреймы с 31-го становятся отдельными событиями `LOG`; с `-e` они пропадают без пометки.

### Производительность (Tier 1, `-1`)

| Вход | Время | Max RSS | Байт на выходе |
|---|---|---|---|
| 1k строк / 0.1 МБ | 0.01 с | 11 МБ | −79% |

## 4. Tier 2 на YAML/JSON

**Нейронный путь не работает в принципе.** `lingua.rs` запрашивает модель
`microsoft/llmlingua-2-bert-base-multilingual-meetingbank`. Hugging Face API отвечает на неё `401`
(модели нет или доступ закрыт), а `microsoft/llmlingua-2-xlm-roberta-large-meetingbank` отдаёт `200`.
Python падает с `OSError: … is not a valid model identifier`, но stderr подпроцесса отбрасывается
(`lingua.rs:52,61-69`), и молча включается fallback. Цена: 63 с на первом запуске (uv собирает
окружение torch+transformers), затем около 4 с на каждый вызов — в том числе в auto-режиме на любом
«похожем на код» входе. Альтернативную модель (~2 ГБ) я не проверял: код её не использует.

**Fallback (pure Rust pruner), `-2 -r 0.4`:**

| Вход | Байт | YAML/JSON валиден | Что изменилось |
|---|---|---|---|
| Deployment | 2348 → 2317 (−1.3%) | ✅ | image, ports, resources не тронуты. **Значение env `FEATURE_FLAGS` переписано** (`"…is enabled for all of the users…"` → `"…enabled all the users…"`), аннотация `description` тоже |
| CRD | 3376 → 3288 (−2.6%) | ✅ | изменены 10 полей `description` |
| JSON в одну строку | — | ❌ **ломается** | `{"to": 1, "and": 2, …}` → `1, 2, 3, 4, …`; `"a": "to be or not to be"` → `"to or not to` |

Почему так (`lingua.rs:102,112`): строки из ≤3 слов не трогаются — поэтому YAML формата `key: value`
выживает. В остальных строках удаляются стоп-слова на чётных позициях, включая ключи JSON и значения
в кавычках. Параметр `-r` используется только как порог `< 0.8`, и обещанных 40% не получается:
выходит 1–3%. Отрицательные значения и `NaN` принимаются без ошибки. Поле конфига `lingua.method`
(`"uv"`/`"builtin"`) кодом не читается.

**Fallback без uv/Python работает** (нет `uv` ни в `PATH`, ни в `$HOME/.local/bin` → сразу builtin, <10 мс), но при наличии `uv` нет
способа отключить попытку нейронного пути, а сама она не ограничена по времени (`wait_with_output`
без тайм-аута) и использует незакреплённые зависимости (`llmlingua>=0.2.2`, `torch`, `transformers`).

**Auto-режим уходит в Tier 2 на обычных логах.** Если больше 85% строк не содержат слов уровня
(access-лог nginx, dmesg) и строк ≥30, вход считается «кодом» (`masker.rs:408`, `main.rs:219`).
Access-лог на 200 строк в auto даёт 201 строку (сжатие 0%), в режиме `-1` — 8 событий (−96%).
При наличии uv при этом запускается torch.

## 6. Находки по приоритету

### Критично

**C1. Нет маскировки секретов ни в одном режиме.**
`src/masker.rs:108-121` (маска только для шаблона), `src/masker.rs:387-395` (печатается сырая строка), `src/main.rs:182-194` (JSON).
Воспроизведение: раздел 2, 11/11 секретов в `-1`/`-j`/`-2`/auto.
Фикс: модуль `redact.rs`, вызывать сразу после чтения строки — до кластеризации, JSON, Tier 2 и Tier 3.
Шаблоны: `(?i)authorization:\s*(bearer|basic)\s+\S+`, JWT `eyJ[\w-]+\.[\w-]+\.[\w-]+`, userinfo в URL
`([a-z][a-z0-9+.-]*://)[^/\s:@]*:[^@\s/]+@` → `$1<REDACTED>@`, `AKIA[0-9A-Z]{16}`,
`(?i)(password|passwd|pwd|secret|token|api[_-]?key|access[_-]?key)\s*[=:]\s*\S+`, `aws_secret_access_key`.
Флаг `--no-redact` — только явный opt-out. Добавить регрессионный тест с этой фикстурой.

**C2. Auto-режим без спроса отправляет сырой лог и ключ в сеть.**
`src/main.rs:226-241`, `src/config.rs:82,103,107,218-229`, `src/ai.rs:77`.
Воспроизведение: раздел 2 (заглушка, 11/11 секретов в теле запроса, `Bearer $OPENAI_API_KEY`; `-e` на 200k строк → AI-сводка).
Фикс: auto никогда не ходит в сеть — Tier 3 только по явному `-3`. Перед отправкой — redaction и лимит размера
(например, 32 КБ). Убрать fallback на `OPENAI_API_KEY` (или явная переменная `LOG_SQUEEZE_API_KEY`).
Отказывать в отправке ключа по `http://` на не-loopback адрес. `-e` всегда возвращает строки, а не сводку.

**C3. klog-строки поглощаются как стектрейс.**
`src/masker.rs:156-168` (`.go:` → стектрейс), `src/masker.rs:249-256`.
Воспроизведение: `klog.log` из 8 строк → `Stack Trace (6 lines)`, `Errors: 1` вместо 3; поглощённые строки не учитываются в статистике.
Фикс: строка с явным заголовком (`^[IWEF]\d{4} `, timestamp, `level=`) никогда не продолжает стектрейс.
Признаки стека проверять по позиции (`^\s+at `, `^\t/.*\.go:\d+`, `^\s+File ".*", line \d+`), а не через `contains`.

**C4. `-e` выбрасывает стектрейсы Go/Python/Rust и OOM-kill.**
`src/masker.rs:249-256,303-307`, `src/masker.rs:132-151`.
Воспроизведение: `go.log -e` → одна строка `panic:`; `python.log -e` → 2 строки; `journal.log -e` — нет OOM.
Фикс: конечный автомат блоков стека — `Traceback` открывает блок, который закрывается строкой `XxxError:`;
`panic:`/`goroutine N [` открывает блок до пустой строки или `exit status`; `stack backtrace:` для Rust.
Блок наследует уровень своей ошибки. Добавить уровни для `Out of memory`, `Killed process`, `segfault`, `OOMKilled`.

**C5. Один байт не-UTF-8 → ноль вывода.**
`src/main.rs:151,153`.
Воспроизведение: `printf 'ERROR \xff\n' | log-squeeze -1` → exit 1.
Фикс: читать байты (`read_until(b'\n')`) и делать `String::from_utf8_lossy` построчно; бинарные куски маркировать `<BINARY n bytes>`.

**C6. Tier 2 молча искажает данные: ломает JSON и переписывает значения.**
`src/lingua.rs:98-124`.
Воспроизведение: `echo '{"to": 1, "and": 2}' | log-squeeze -2` → `1, 2}`; env `FEATURE_FLAGS` в Deployment переписан.
Фикс: для входа, который парсится как JSON/YAML, — структурный режим: удалять `description`, `managedFields`,
`status`, свернуть дубли, но никогда не трогать скаляры. Для прозы не трогать текст в кавычках и токены с `:`/`=`.

### Важно

**I1. Разные ошибки склеиваются из-за маскировки чисел.** `src/masker.rs:97-101,267-275`. Воспроизведение: 200/500/502/200 → `[x4]`, 5xx не видны.
Фикс: не склеивать события ERROR/WARN, если немаскированные «смысловые» токены различаются; для склеенных выводить
набор значений (`code ∈ {401,402,500,503}`); 3-значные HTTP-коды не маскировать.

**I2. Бюджет ломает хронологию.** `src/masker.rs:354-383`. Воспроизведение: `order.log` (1000 строк) — ERROR из строки 500 на 3-й позиции.
Фикс: выбирать индексы, сортировать по исходной позиции, вставлять маркеры `… N events skipped`.

**I3. `max_lines` не ограничивает вывод; с `-e` бюджета нет.** `src/masker.rs:354,360`. 2407 строк при бюджете 200; 161 строка при `-e -m 5`.
Фикс: жёсткий лимит строк после фильтрации, считая строки стектрейсов; при переполнении склеивать повторы и усекать стеки с пометкой `(+N frames)`.

**I4. Только последовательная дедупликация; ошибки со стеком не склеиваются.** `src/masker.rs:267-286,272`. Реалистичный лог: 0.1% по событиям; 40 одинаковых NPE → 160 строк.
Фикс: глобальный `HashMap<template, cluster_id>` с выводом в порядке первого появления (`[x40] first … last`);
сравнивать стек по маскированному шаблону.

**I5. Уровень определяется по подстроке.** `src/masker.rs:132-151`. `INFO no panic detected` → PANIC, `GET /api/errors 200` → ERROR, `level=info msg="warning…"` → WARN.
Фикс: сначала разобрать явное поле уровня (`[INFO]`, ` INFO `, `level=`, `"level":30`, klog `I/W/E/F`), и только потом — эвристику по границам слов.

**I6. Битый конфиг молча заменяется дефолтами с включённым LLM.** `src/config.rs:194-212`. `max_lines = "200"` + `enabled = false` → запрос на `localhost:11434`.
Фикс: при ошибке парсинга выводить её и завершаться с ошибкой (fail-closed); никогда не включать сеть по умолчанию.

**I7. Ключ API в файле, который читают все.** `~/.config/log-squeeze/config.toml` имеет права `0664` и содержит `api_key`; файл создаётся через `fs::write` с umask (`src/config.rs:207`); `--key` виден в `ps`.
Фикс: создавать конфиг с правами `0600` и предупреждать, если права шире; брать ключ из переменной окружения или файла (`--key-file`), а не из argv. **Сейчас: `chmod 600 ~/.config/log-squeeze/config.toml`.**

**I8. Auto включает Tier 2 на обычных логах; подпроцесс uv без тайм-аута и с незакреплёнными зависимостями.** `src/masker.rs:408`, `src/main.rs:219-224`, `src/lingua.rs:36-70`. nginx-лог: 0% вместо 96%.
Фикс: эвристика «код» по реальным признакам (YAML/JSON-парсинг, отступы), а не по отсутствию слов уровня. Тайм-аут
на подпроцесс; выводить stderr при неудаче; закрепить версии; уважать `lingua.method`; исправить имя модели.

**I9. Память 12× от входа.** `src/main.rs:148-154,174`, `src/masker.rs:356,382`. 1M строк / 82 МБ → 1 ГБ RSS.
Фикс: потоковая обработка `BufRead` из stdin/файла; `partition` без `clone()`; хранить пример кластера, а не все строки.

**I10. Clippy/fmt падают, в CI их нет.** `.github/workflows/ci.yml`. 8 ошибок clippy, 24 диффа fmt.
Фикс: добавить `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo audit` (или `cargo deny`),
`cargo build --target x86_64-unknown-linux-musl`; закрепить actions по SHA; добавить `permissions: contents: read`.

**I11. Противоречивые комбинации флагов проходят молча.** `src/main.rs:59-112,160-201`. `-2 -e` (фильтр игнорируется), `-3 -j` (без AI), `mode = "fastt"` (= auto), `-r -5`/`NaN`, два файла, `-`.
Фикс: валидировать (`0 < rate ≤ 1`, известные режимы, ровно один файл, `-` = stdin) и сообщать о конфликтах.

**I12. Паника на SIGPIPE.** `src/main.rs:194` (и все `println!`). `-j big.log | head -1` → exit 101.
Фикс: писать через `stdout().lock()` и считать `ErrorKind::BrokenPipe` нормальным завершением.

**I13. Тесты слабые и выполняются дважды.** 6 тестов, `assert!(contains(..))`; нет тестов CLI, Tier 3 (с заглушкой), redaction, klog/Go/Python; `main.rs:1-4` дублирует модули из `lib.rs`.
Фикс: `main.rs` использует `log_squeeze::…`; golden-тесты на фикстуры из этого ревью (`tests/fixtures/*.log` + ожидаемый вывод);
тест «нет сетевых вызовов в auto»; точные `assert_eq!` (по правилам AGENTS.md §6).

## Топ-5 изменений по пользе

1. **Слой redaction на входе** (C1). Одна функция, вызываемая для каждой строки до всех тиров, плюс регрессионный тест
   с фикстурой секретов. Закрывает главную угрозу для агентского сценария.
2. **Auto-режим без сети** (C2, I6, I7, I8). Tier 3 и uv только по явному флагу; fail-closed на битом конфиге; без
   fallback на `OPENAI_API_KEY`; лимит размера запроса; `chmod 600` конфига. Утилита из AGENTS.md перестаёт неожиданно ходить в сеть.
3. **Правильный разбор уровней и стектрейсов** (C3, C4, I5). Явное поле уровня (klog, logfmt, JSON) и конечный автомат
   блоков для Go/Python/Rust/Node; `-e` сохраняет блок целиком. Чинит основные целевые форматы: `kubectl logs`, `journalctl` с rke2/kubelet.
4. **Не терять различающиеся ошибки и порядок** (I1, I2, I3, I4). Не склеивать ERROR с разными значениями (или
   показывать набор значений), бюджет с сохранением порядка и маркерами пропусков, жёсткий лимит строк, глобальная дедупликация.
5. **Надёжный ввод и CI** (C5, C6, I9, I10, I12). Построчный lossy-UTF-8 потоковый ридер, Tier 2 без порчи
   JSON/YAML (или отключить его до исправления модели), clippy/fmt/audit и golden-тесты в CI, README приведён в соответствие с кодом.
